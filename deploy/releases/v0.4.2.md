# v0.4.2 — WireGuard 存储短暂卡顿容错

数据库或磁盘短暂卡顿时，旧版可能因单次续期失败或统计写入阻塞而永久暂停 WG 节点，即使出口 VPS 正常、数据库随后恢复，也需要人工恢复。

本版将 WG 统计保存与续期分开运行，并在已确认的租约安全窗口内重试临时数据库错误。窗口以最近一次成功申请或续期操作的开始时间计算，最多 20 秒；数据库租约仍为 30 秒。失败、取消和过晚的响应不会延长窗口。

- 统计保存卡顿不会直接阻塞续期。
- 短暂数据库故障在安全窗口内恢复后，可以继续使用原 WG 运行实例。
- 人工暂停、节点过期、配置变更或租约所有权丢失仍会关闭连接；无法核对节点状态的新请求仍会失败。
- 超出安全窗口仍关闭并锁定节点，需要手动恢复；不会绕过 WG 直连。
- 新增分阶段日志，区分统计写入失败、控制面暂时异常、恢复和租约超时。日志不包含原始数据库错误或密钥，并跳过数据库系统日志索引。

## 更新与验收

本版无数据库结构变更，不修改 PostgreSQL 持久化设置，也不关闭流量或带宽监控。升级不会自动解锁已经暂停的节点。可先在后台恢复节点、验证出口与正常请求，再按后台更新流程升级；遇到更新器预检查提示时按提示处理。

更新后确认版本为 0.4.2，并验证 WG 出口和实际业务请求。若再次发生，保留 `wireguard.*` 事件及同时间段的 I/O 采样，交叉核对。需要回退时使用原 v0.4.1 镜像和既有部署回退流程。

## 验证范围

- WG 与出口路由包的竞态检测测试。
- 故障注入：统计写入阻塞 22 秒、续期调用阻塞 14 秒、延迟申请/续期响应、人工暂停、租约失效及错误后的恢复行为。
- WireGuard / ServiceTraffic 数据库集成测试，使用本地临时 PostgreSQL 17.11；生产 PostgreSQL 18.6 的故障环境未复现。
- Linux amd64 后端交叉构建；正式镜像仍需发布流水线构建前端、打包并验证。

以上验证不代表 VPS 底层存储问题已经消失，也不保证任意时长 I/O 故障期间业务请求不中断。
